## F01 — AI Builder (generate-site)

Error handling lives in:
- `src/lib/generation-errors.ts` — canonical error map (SSE stream)
- `src/app/(builder)/builder/new/AIBuilderPageClient.tsx` — client-side display
- `src/app/api/ai/generate-site/route.ts` — API route

### Error Scenarios

| Code | HTTP | User-facing message (EN) | Retryable |
|------|------|--------------------------|-----------|
| `PAYMENT_REQUIRED` | 402 | "You've used your free AI generation. Upgrade to Pro for unlimited creations." | No — shows Upgrade CTA |
| `RATE_LIMIT` | 429 | "Too many requests. Please wait {seconds}s before trying again." | Yes — countdown retry |
| `CONTENT_UNSAFE` | 400 + code | "Your input contains content that cannot be processed. Please revise your business description." | No — shows Edit CTA |
| `VALIDATION_ERROR` | 400 | "Some fields are invalid. Please check your input and try again." | No — shows Fix & retry |
| `UNAUTHORIZED` | 401 | "Your session has expired. Please sign in again." | No — shows Sign in CTA |
| `TIMEOUT` | 408 | "Generation timed out. Please try again — your input has been saved." | Yes |
| `SERVER_ERROR` | 500 | "Something went wrong on our end. Please try again in a moment." | Yes |
| `SERVICE_UNAVAILABLE` | 503 | "AI service is temporarily unavailable. Please try again in a few minutes." | Yes — 60s delay |
| `SSE_DISCONNECT` | 0 | "Connection lost during generation. Please try again." | Yes |
| Draft save fail | client | toast: "Failed to save the latest preview changes." | — |
| Publish fail | client | toast: `error.message` OR "Failed to publish website" | — |
| Rate limit (generate-site route) | 429 | "Rate limit exceeded. Please wait before trying again." | — |
| Free tier limit (Vietnamese msg) | 402 | "Tài khoản Free chỉ được tạo website bằng AI 1 lần duy nhất. Vui lòng nâng cấp gói cước để tiếp tục." | — |

**Notes:**
- Free-tier users see Vietnamese-language quota message directly from the route (`generate-site/route.ts` line 224).
- On timeout, the client sets a 90s generation timer before firing the timeout error.

## F05 — AI Editor (edit-block / AI chat panel)

Error handling lives in:
- `src/app/api/ai/edit-block/route.ts` — SSE stream, block edit
- `src/components/editor/AIChatPanel.tsx` — chat UI error display
- `src/app/(editor)/editor/[siteId]/page.tsx` — editor-level toasts

### Error Scenarios

| Trigger | User-facing message |
|---------|---------------------|
| Missing `OPENAI_API_KEY` | "AI editing requires OPENAI_API_KEY. Please set it before using chat editing." (HTTP 503) |
| Rate limit hit | "Rate limit exceeded. Try again later." (HTTP 429) |
| AI request processing failure | SSE event `error`: "Failed to process AI request. Please try again." |
| AI editing general failure | "AI editing failed. Please try again later." (HTTP 500) |
| Empty AI response | Internal `throw new Error('Empty AI response')` → caught, returns 500 |
| Unknown block type | Internal `throw new Error('Unknown block type: ...')` → caught, returns 500 |
| Invalid block from AI | Internal: "Invalid block generated by AI" → caught, returns 500 |
| Failed to load site | toast: "Failed to load site" (with server message as description) |
| Save failed | toast: "Save failed" (with server message as description) |
| Failed to update site settings | toast: "Failed to update site settings" / "Please try again later." |
| Unable to add section | toast: "Unable to add this section yet" |
| Nothing to undo | toast: "Nothing to undo" |
| Publish failed | toast: `t.editor.toast.publishFailed` (i18n key, both publish paths) |
| Failed to update page settings | toast: "Failed to update page settings" |
| AIChatPanel — SSE error event | `payload.error` OR i18n `ac.editFailed` |
| AIChatPanel — fetch failure | `data.error` OR i18n `ac.failedToEdit` |
| AIChatPanel — network error | `err.message` OR "Unknown error" |

**Notes:**
- AI text rewrite (`rewrite-text/route.ts`): returns `{ error: 'AI rewriting requires OPENAI_API_KEY' }` (503) and `{ error: error.message || 'Rewrite failed' }` (500).
- Editor uses i18n keys (`t.editor.toast.*`) for publish errors; actual EN strings are in locale files not searched here.

## Key Observations

1. **F01 AI Builder** has the most complete, structured error system (`generation-errors.ts`) with bilingual EN/MS messages, retry flags, and CTA actions. All errors are derived from HTTP status codes on the SSE stream.

2. **F05 AI Editor** error messages are a mix of hardcoded English strings and i18n keys. The `OPENAI_API_KEY` missing scenario is surfaced directly to the user — a sign this is expected to fail in non-configured envs.

3. **F17 Blog** uses i18n keys for most messages (actual strings in locale files). Server-side category errors use hardcoded English strings returned from `actions.ts`. File upload limits (10MB, JPEG/PNG only) have hardcoded fallback strings in the component.

# Phase 02 — Wire next.config.ts + Middleware Exclusion

**Status:** pending
**Effort:** 30m
**Depends on:** Phase 01 (config files must exist)
**Blocks:** Phase 03

## Goal

Wrap `next.config.ts` export with `withSentryConfig` (outside `withPayload`). Exclude `/sentry-tunnel` from `src/middleware.ts` matcher so tunnel requests reach Sentry's auto-generated route handler.

## Files to modify

| File | Change |
|------|--------|
| `next.config.ts` | Wrap export: `withSentryConfig(withPayload(nextConfig), sentryOptions)` |
| `src/middleware.ts` | Add `sentry-tunnel` to matcher exclusion regex |

## Pre-flight verified

- `src/middleware.ts` line 312 matcher: `'/((?!_next/static|_next/image|favicon.ico|api/).*)'` — extend pattern

## Implementation steps

### 1. Modify `next.config.ts`

Replace the last line `export default withPayload(nextConfig)` with:

```ts
import { withSentryConfig } from '@sentry/nextjs'

// ... existing nextConfig ...

const sentryWebpackOptions = {
  org: process.env.SENTRY_ORG,
  project: process.env.SENTRY_PROJECT,
  authToken: process.env.SENTRY_AUTH_TOKEN,
  silent: !process.env.CI,
  // Do NOT widen — only Next.js bundle dirs get source maps uploaded
  widenClientFileUpload: false,
  // Strip source maps from final bundle after upload (prevents leaking source)
  sourcemaps: {
    deleteSourcemapsAfterUpload: true,
  },
  // Bypass ad-blockers by tunneling Sentry requests through our domain
  tunnelRoute: '/sentry-tunnel',
  // Hide source maps from client devtools
  hideSourceMaps: true,
  // Disable Sentry CLI logger spam in CI
  disableLogger: true,
  // Auto-instrument Vercel cron monitors (no-op if no crons)
  automaticVercelMonitors: false,
}

export default withSentryConfig(withPayload(nextConfig), sentryWebpackOptions)
```

Key invariants:
- `withSentryConfig(withPayload(...))` — Sentry is the OUTER wrapper. Reversing breaks Payload's webpack tweaks.
- `import` goes at top of file, alongside `import { withPayload } from '@payloadcms/next/withPayload'`
- The polyfill block (`globalThis.File`) stays untouched at top of file
- `process.env.VERCEL` standalone branch stays untouched

### 2. Modify `src/middleware.ts`

Update matcher (line 312) from:

```ts
matcher: [
    '/((?!_next/static|_next/image|favicon.ico|api/).*)',
],
```

To:

```ts
matcher: [
    // Excludes: Next.js statics, /api/* (Payload + custom routes),
    // and /sentry-tunnel (Sentry event tunneling — must reach handler unmodified).
    '/((?!_next/static|_next/image|favicon.ico|api/|sentry-tunnel).*)',
],
```

That's the only middleware change. Body of `middleware()` function unchanged — early-exit branches for `/api/` already cover most cases, but matcher exclusion is belt-and-suspenders for the tunnel.

### 3. Add a defensive early-exit in `middleware()` body (optional but recommended)

After the existing `_next` / `favicon` / `public` early-exit block (around line 63-72), add:

```ts
// Sentry tunnel — auto-generated by withSentryConfig. Bypass all routing.
if (pathname.startsWith('/sentry-tunnel')) {
    return NextResponse.next()
}
```

Defense-in-depth: if matcher regex fails on some platform variant, body still bypasses all tenant-domain rewrites for the tunnel.

## Data flow (post-change)

```
Browser                        Next.js                          Sentry SaaS
   │                              │                                  │
   │── error → tunnel POST ──────►│                                  │
   │  /sentry-tunnel              │ middleware: SKIP (matcher)       │
   │                              │ Sentry route handler             │
   │                              │── envelope POST ────────────────►│
   │◄──────────────── 200 ────────│◄──────── 200 ────────────────────│
```

Without the matcher exclusion, middleware rewrites `/sentry-tunnel` → `/sites/{tenant}/sentry-tunnel` on subdomain hosts, which 404s.

## Risks specific to this phase

| Risk | Mitigation |
|------|------------|
| `withSentryConfig` changes `output: 'standalone'` behavior on non-Vercel | Already conditional on `process.env.VERCEL`; verify Docker dev still works in Phase 04 |
| `tunnelRoute` collides with future `/sentry-tunnel` route a dev creates | Highly unlikely; document as reserved path in `docs/architecture/_OVERVIEW.md` (deferred) |
| Sentry webpack plugin slows Turbopack dev | `silent: !process.env.CI` keeps dev quiet; if dev startup > 30s, set `disableServerWebpackPlugin: true` for dev |
| Matcher regex change breaks existing tenant routing | Phase 04 e2e: visit `{tenant}.web-v2.dev.ecommercehub.my/about` after deploy — should still rewrite to `/sites/{tenant}/about` |
| `withSentryConfig` not compatible with `outputFileTracingIncludes` | Sentry 10.x preserves user nextConfig; verify build log shows test-harness routes still traced |

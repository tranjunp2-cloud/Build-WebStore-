# PR #1759 F40-01 scope correction

## Context

PR #1759 implements US-F40-01 Project Health. Review identified a risk that unfinished GitHub issue-mapping work could create a misleading Critical/open-finding result or expand this PR into US-F40-05.

## What Happened

- Preserved the no-false-green guard: a run reported as `passed` must also have a valid completion timestamp before it can contribute a passing signal.
- Restricted Project Health to runtime-backed QA run data; issue mapping, GitHub synchronization, and audit persistence remain outside this PR.
- Removed demo-only Inbox, Run, and GitHub issue flows so the UI cannot show fabricated operational data or success states.
- Added AC-3 trace links and ensured the F40 Project Health E2E spec is included in the staging CI allow-list.
- Added environment-example placeholders required by authenticated E2E setup and tightened F40 test coverage around invalid finished-run data.

## Reflection

Project Health is a release signal, so a partially wired risk input is worse than an omitted one: it can falsely imply a critical state or falsely claim a clean one. The correct narrow fix is to calculate only from authoritative persisted run data and defer the separate integration surface explicitly.

## Decisions

- Keep PR #1759 scoped to US-F40-01; do not add collection/schema/API work for issue mapping.
- Defer GitHub issue sync, issue-to-test mapping, critical/open-finding aggregation, and audit history to US-F40-05.
- Treat `passed` records without a parseable `finishedAt` value as non-passing evidence.
- Require staging CI to discover the F40 browser spec rather than leaving it outside the Playwright project allow-list.

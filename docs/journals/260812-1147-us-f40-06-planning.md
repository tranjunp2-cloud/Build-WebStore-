# Journal: 2026-08-12 — US-F40-06 Planning

## Context

Planned US-F40-06, the QA Control Center workflow for reviewing failed-test findings and manually promoting a confirmed finding to one GitHub ticket.

## What Happened

- Established the lifecycle from failed result to deduplicated finding, human review, explicit GitHub promotion, and fix verification/reopen.
- Identified F40-04 as the source of trusted QA test runs/results and evidence, and F40-05 as the existing GitHub issue integration and mapping foundation.

## Reflection

This story must keep automation confined to evidence collection and finding lifecycle. Creating an external GitHub issue is a deliberate reviewer action, not a side effect of a failing test.

## Decisions Made

| Decision | Rationale | Impact |
|---|---|---|
| Use a global finding fingerprint and PostgreSQL advisory lock | Concurrent or repeated runs must converge on one active finding for the same defect | Prevents duplicate active findings across runners and targets consistently |
| Make GitHub promotion explicit and idempotent | A reviewer controls issue creation; retries must not create a second ticket | Persist an immutable promotion marker/mapping before or atomically with the external action, then return the already-created issue on repeat requests |
| Depend on F40-04 and F40-05 contracts | Findings reuse sanitized evidence/test-run context and promotion reuses GitHub mapping behavior | Avoids a parallel runner or GitHub integration path |

## Next

- Implement the planned schema, migration, lifecycle services, review UI/API, and tests after the prerequisite F40-04/F40-05 contracts are available.
- Keep all GitHub payload evidence sanitized and include target, severity, reproduction information, and a stable marker for traceability.

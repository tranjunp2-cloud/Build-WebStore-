## `llms.txt` Content-Coverage Reconciliation — 2026-07-31

- A local simulated custom-domain run for TC-F37-03-52 exposed blog starvation in `llms.txt`: sequential page/product/blog concatenation followed by `slice(0, 10)` allowed earlier groups to consume the bounded result.
- This revealed a contract conflict between TC-F37-03-16's 10-URL cap and TC-F37-03-52's requirement that available product and blog detail URLs be advertised.
- The decision retains the 10-URL cap and homepage-first behavior, then selects pages, products, and blogs in deterministic round-robin order while preserving oldest-first order within each group.
- PR #1719 review closeout on 2026-08-03 removed the candidate query caps: sitemap serializes every matching published record, while `llms.txt` fetches every matching candidate with narrow projections before applying the 10-URL selector. This matches the issue contract without silently omitting later products or blogs.
- Sitemap and llms successful responses now use `Cache-Control: no-store`; otherwise a recently unpublished storefront could continue returning a CDN-cached 200 despite the origin's published-site guard.
- Product/blog discovery now accepts only one encoded slug segment, matching the actual `[productSlug]` and `[blogSlug]` routes. Legacy invalid rows are omitted, and the Blogs collection rejects new nested slugs.
- The authenticated site-status summary now requests at most two records, which bounds the lookup while retaining enough information to fail closed when the one-account/one-tenant/one-site invariant is violated.
- The earlier round-robin regression failed before its implementation change and passed afterward. For the 2026-08-03 closeout, the four review findings produced eight failing assertions across four suites before the fixes; the expanded focused gate then passed 90/90, followed by clean typecheck and lint with only pre-existing warnings.

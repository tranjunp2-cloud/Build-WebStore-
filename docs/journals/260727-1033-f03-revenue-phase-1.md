# Journal: 2026-07-27 — F03 Revenue aggregation Phase 1

## Context

Phase 1 prepared the dashboard Revenue metric for activation. The work replaced the capped order-document reads with a tenant-scoped aggregate and established one UTC date contract for every At-a-glance metric. The Revenue card remains in its pre-activation UI state until Phase 2.

## What Happened

- Added `DASHBOARD_TIME_ZONE = 'UTC'` and pure helpers for exact, half-open today/7d/30d windows, equal comparison windows, UTC labels, and deterministic day keys.
- Applied the shared UTC bounds and SQL day grouping to Views, Leads, Engagement, and Revenue without changing the three existing event definitions.
- Replaced two `payload.find(... limit: 2000)` Revenue reads with one parameterized aggregate over the previous and current windows.
- Revenue now includes only the authenticated tenant's current `completed` orders, uses `createdAt` for attribution, accepts MYR and legacy null currency, and applies no payment-method, payment-status, or COD predicate. Revenue SQL is gated by the existing Orders permission boundary; denied users receive zero/empty Revenue.
- Current total, previous total, percentage delta, and zero-filled sparkline all derive from the same aggregate rows. Malformed numeric rows normalize safely instead of propagating `NaN`.
- Focused tests passed 10/10, the dashboard unit suite passed 1,074/1,074, `npm run typecheck` passed, and `git diff --check` passed.
- Hardened AC-R05 for finite operands whose arithmetic still overflows IEEE-754: Revenue totals are normalized after aggregation and every `pctChange` result is normalized after subtraction, division, and multiplication.
- Added a RED→GREEN regression using `1e308` and `1e-308`. Before the guards, the case exposed `Infinity` in the Revenue total and Views delta; afterward all returned stat values, deltas, and spark points remain finite.
- Re-verified in Docker: the focused `glance-data` suite passed 6/6, TypeScript and the production build passed, and lint exited 0 with only the repository's pre-existing warnings.

## Reflection

Centralizing the period contract removed several subtle inconsistencies at once: host-local day boundaries, database-session-dependent grouping, unequal comparison ranges, and an unbounded current window. Using one Revenue result set also keeps the card total, delta, and sparkline aligned while eliminating the 2,000-order truncation risk. Checking only parsed operands was insufficient because two finite numbers can produce a non-finite aggregate or percentage; AC-R05 therefore needs guards at arithmetic boundaries, not only input boundaries. The remaining performance question is operational rather than a correctness blocker: the aggregate still needs read-only `EXPLAIN ANALYZE` against representative staging-like data before release confidence is complete.

## Decisions Made

| Decision | Rationale | Impact |
|---|---|---|
| Count only orders whose current status is `completed` | Product defines Revenue from the present order state | Refunded or otherwise non-completed orders are excluded retroactively |
| Attribute Revenue to `createdAt` | No `completedAt` field exists and product selected creation date as fallback | Late completion appears on the original UTC creation day; no schema or migration needed |
| Treat `currency = 'MYR'` and legacy null currency as MYR | Current dashboard supports RM only | USD, SGD, and other non-null currencies do not contribute |
| Use one shared UTC constant across all four metrics | Date boundaries and grouped day keys must be host- and session-independent | Today/7d/30d behavior is consistent at UTC midnight |
| Reuse the existing Orders permission gate for Revenue | Revenue is order-derived data and follows AC-R06 | Denied users trigger no Orders query and receive zero/empty Revenue; tenant isolation remains mandatory |
| Aggregate previous and current Revenue in one query | Avoid pagination caps and predicate drift | Total, comparison, and series share identical inclusion rules |
| Normalize after aggregation and percentage arithmetic | Finite operands can overflow during addition or ratio calculation | The serialized dashboard contract cannot emit `NaN` or `Infinity` for AC-R05 |

# PrimeWeb static prototypes

The nine prototype suites are generated review artifacts for the Prime Web v2 migration. They originated from live Vue templates, but their block markup must now come from actual Prime Web v2 React renderers and migrated preset data.

Each template remains a standalone review site with pre-rendered HTML, local CSS/images/fonts, no Vue runtime, and no review-time API dependency. The HTML is output, not source: edit migration data/renderer inputs and rerun the exporter instead of hand-editing generated block markup.

Current phase constraints:

- Review every manifest route in each of the nine generated template suites; homepage-only completion is not template completion.
- Render 100% of seedable sections with blocks/variants already available in `src/blocks/registry.ts`; a handwritten look-alike section does not qualify.
- Migrate legacy content into `TemplatePreset`-compatible block configs and preserve field values, media, order, links and relationships as closely as the destination schemas allow.
- Use existing storefront runtime components for PDP, Blog detail, Cart, Checkout and Orders; do not rebuild their business behavior in prototype JavaScript.
- Do not add/fork a production block or change schemas merely to preserve legacy markup. Record unsupported data as an explicit migration gap.
- Do not publish/write migrated records to shared Payload environments or the template library before review approval.
- Annotate adapted sections with `data-block-type`, `data-block-variant` and `data-mapping-status`.
- Generate each section's visible DOM from the mapped v2 renderer; annotations and hand-authored DOM alone do not count as adaptation.
- Use [`../component-adaptation-mapping.md`](../component-adaptation-mapping.md) as the authoritative legacy → v2 replacement guide.
- The export must be reproducible from migrated data plus renderer revision. Generated HTML may be checked in for review, but manual fixes to it are invalid.

Run locally from this directory:

```bash
python3 -m http.server 4173
```

Then open `http://localhost:4173/`.

Rebuild the renderer-generated C101 prototype:

```bash
STATIC_PROTOTYPE_BASE_URL=http://127.0.0.1:3000 node scripts/export-static-prototypes.cjs c101
```

The incremental Next renderer exporter currently supports C101. C102 uses its own renderer-provenance exporter:

```bash
node scripts/export-static-prototypes.cjs c101
node c102/generate.mjs
```

Run the C102 command from this `static-prototypes` directory. It recreates all 9 outputs from `c102/source/templates`, validates local references, renderer/runtime, shared-navigation, Product filter, Articles newsletter-removal and zero-offset `navigationOffsetContract` guards, then refreshes `c102/manifest.json` plus `c102/renderer-contract.generated.json`.

Verify C101 export provenance and snapshot invariants:

```bash
node scripts/verify-static-prototypes.cjs
```

Remove unavailable optional/placeholder media after an export:

```bash
node scripts/cleanup-static-prototype-media.cjs
```
